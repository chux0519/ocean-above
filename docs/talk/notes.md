# 讲稿：Ocean Above 的开发过程（15 分钟，22 页）

演示稿是 [vibe-process.html](vibe-process.html)，用浏览器打开即可。

**操作**
- 翻页：方向键、空格、点击屏幕右侧 2/3 或滑动；点击左侧 1/3 是后退。
- 同一页的内容会分几步出现，按一次显示一步。
- 其他按键：F 全屏；E 进入编辑模式，可以直接改文字；Ctrl/Cmd+S 下载改过的副本。
- 网址后面加 `#N` 可以直接打开第 N 页。

**嵌入页**：`bench.html`（405 次运行的矩阵，点格子看对话）和 `trace.html`（真实 trace 回放，点 span 看属性）也能单独打开。数据由 `tools/build_bench_data.py`（来自 12-bench 的 N=3 结果）和 `tools/capture_traces.py`（用真实模型跑 3 个用例，span 经过 app 的脱敏导出）生成。

**线上地址**：`https://ocean-above.potafree.net/talk/`。页面不在 app 里链接，响应头带 noindex。

**生成方式**：用 [frontend-slides](https://github.com/zarazhangrui/frontend-slides) skill 的 Cobalt Grid 模板制作，文字按 Humanizer-zh 的规则改写过。

**导出**：运行 `./render.sh` 生成 `vibe-process.pdf`，所有动画都显示为最终状态。加 `--png` 会把逐页预览图输出到 `png/`（这个目录不进 git）。

**注意**：字体从 Google Fonts 加载。现场没有网络时，会退回系统字体。

**数字来源**：DESIGN.md 的“Key numbers”、各迭代的 `acceptance.md` / `STATE.md`、`docs/design/adr-001-agent-runtime.md`、`docs/iterations/12-bench/results/n3/bench.md`。

## 可能被问到的问题
- **花了多少钱？** 真实模型 eval 每次几美分，上限是 $0.25；bench 里 DeepSeek 官方 API 这组配置跑了 135 次，共 $0.109。
- **为什么不用 LangChain？** 依赖要尽量少。SDK 只负责通用的 loop；订票、ReplyGuard、预算这些边界都是自己的代码（见 ADR-001）。
- **人到底写了多少代码？** 我的工作是需求、取舍、授权和验收；全部原始会话都在 `prompt history/`。
- **多个 worker 改同一个文件怎么办？** 一个任务对应一个分支和一个 worktree，计划里写明每个 worker 负责哪些文件；后合并的一方负责解决冲突（见 11-followup 计划）。
