# API and card contract (v1, 2026-11-23)

Single source for the frontend (T6) and backend (T2/T3/T5). Change it only through the coordinator. Examples live in
`contract/fixtures/`; both sides' tests load them. Numbers in fixtures are **illustrative** (computed with a quick
script, not by the production core) — correctness is tested in the backend, not by these files.

## Conventions
- Same origin, JSON, paths under `/api`. Session cookie `oa_session` (httpOnly, SameSite=Lax, `Secure` by env).
- Times: ISO 8601 UTC strings. IDs: opaque strings with a type prefix (`u_`, `c_`, `m_`, `q_`, `t_`).
- **The frontend never formats or computes numbers.** Every number shown comes from a `*_display` field.
  High-precision values (`distance`, `price`, decimal strings) are only shown in the trace view.
- Errors: HTTP status + `{"error": {"code": "<snake_case>", "message": "<human text>"}}`.
  Common codes: `unauthorized` (401), `not_found` (404; also for other users' objects), `bad_request` (400),
  `rate_limited` (429), `llm_unavailable` (503).

## Endpoints

| Method | Path | Request | Response |
|---|---|---|---|
| GET | `/api/health` | – | `{"status":"ok","network_fingerprint":"sha256:…"}` |
| GET | `/api/config` | – | `{"dev_login":true,"google_client_id":null}` |
| POST | `/api/auth/dev` | `{"username","password"}` | `User` + sets cookie; 401 `invalid_credentials` |
| POST | `/api/auth/logout` | – | `{"ok":true}` |
| GET | `/api/me` | – | `User` or 401 |
| GET | `/api/conversations` | – | `{"conversations":[ConversationSummary]}` newest first |
| POST | `/api/conversations` | `{}` | `ConversationSummary` |
| GET | `/api/conversations/{id}` | – | `Conversation` (messages oldest first; card states are current server state) |
| POST | `/api/conversations/{id}/messages` | `{"text"}` | **SSE stream** (below) |
| POST | `/api/quotes/{id}/book` | `{"nonce"}` | `{"ticket": TicketCard, "message": Message}` or error (below) |
| GET | `/api/quotes/{id}/trace` | – | `Trace` |
| GET | `/api/tickets` | – | `{"tickets":[TicketCard]}` newest first |
| GET | `/api/debug/sse-ping` | – | SSE: `ping` with `{"seq":n}` immediately, then every 2 s, 5 events total |

Booking errors: `invalid_nonce` (409), `not_presented` (409), `expired` (409), `already_booked` (409),
`stale` (409; data changed — ask for a new quote), `not_found` (404), `conversation_busy` (409; a reply is still
being generated — retry after `done`), `data_unavailable` (503; route data could not be read — retry; the quote and
nonce are unchanged).

## Objects

```ts
type User = { id: string; display_name: string; auth_provider: "dev" | "google" }
type ConversationSummary = { id: string; title: string; created_at: string; updated_at: string; preview: string }
type Conversation = ConversationSummary & { messages: Message[] }
type Message = {
  id: string; role: "user" | "assistant" | "system"   // system = booking results etc.
  text: string                                        // markdown for assistant; plain for user
  cards: Card[]; created_at: string
}
type Leg = { from: string; to: string; distance_display: string; distance: string }
type CardState = { status: "quoted" | "presented" | "booked" | "expired" | "stale";
                   bookable: boolean; nonce: string | null; ticket_id: string | null }

type Card = QuoteCard | BookingRequestCard | TicketCard | TicketListCard | NoServiceCard
          | AmbiguousCityCard | UnknownCityCard | NoticeCard

type QuoteCard = { type: "quote"; id: string /* q_ */; origin: string; destination: string
  legs: Leg[]; transfers: string[]; distance_display: string; price_display: string
  distance: string; price: string; expires_at: string; state: CardState }
type BookingRequestCard = Omit<QuoteCard, "type"> & { type: "booking_request" }   // id is the quote id
type TicketCard = { type: "ticket"; id: string /* t_ */; quote_id: string; origin: string; destination: string
  legs: Leg[]; transfers: string[]; distance_display: string; price_display: string; booked_at: string }
type TicketListCard = { type: "ticket_list"; count: number; filter: Record<string, string>; tickets: TicketCard[] }
type NoServiceCard = { type: "no_service"; city: string
  nearest: { city: string; distance_display: string }[] }          // up to 3, nearest first
type AmbiguousCityCard = { type: "ambiguous_city"; query: string
  candidates: { city: string; is_hub: boolean; connected_hubs: string[] }[] }
type UnknownCityCard = { type: "unknown_city"; query: string; suggestions: string[] }
type NoticeCard = { type: "notice"; code: "same_city" | "unreachable" | "quote_expired" | "stale"; message: string }

type Trace = { quote_id: string; formula: string; algorithm: string; network_fingerprint: string
  legs: (Leg & { from_coord: [number, number]; to_coord: [number, number]; source: string })[]
  distance: string; price: string; distance_display: string; price_display: string; note: string }
```

Card buttons: a quote or booking-request card shows **Confirm booking** only when `state.bookable` is true; clicking
posts `{"nonce": state.nonce}` to `/api/quotes/{id}/book`. While a stream is running, buttons stay disabled until
`done`; after `done` (or on reload) the card state from the server wins.

## SSE stream (`POST /api/conversations/{id}/messages`)

`Content-Type: text/event-stream`. Each event: `event: <name>\ndata: <json>\n\n`.

| event | data | notes |
|---|---|---|
| `user_message` | `Message` | the stored user message, first event |
| `status` | `{"text":"Looking up routes…"}` | progress, replaceable |
| `card` | `{"card": Card}` | push immediately; state.bookable is false until `done` |
| `delta` | `{"text":"…"}` | append; already validated text (one sentence or more) |
| `replace` | `{"text":"…"}` | replace the whole assistant text so far |
| `ping` | `{}` | heartbeat every 15 s; ignore |
| `done` | `{"message": Message}` | final assistant message incl. cards with current states |
| `error` | `{"code","message"}` | stream ends; the user message is kept |

Example: `contract/fixtures/sse_quote_turn.txt`.

## 1. 做了什么

### store（`backend/app/store/`）
- `db.py`：`Store(path, clock=utc_now)`。每次操作开一个连接（线程间可共享 `Store`）；`Store.write()` 是一个
  `BEGIN IMMEDIATE` 事务（正常退出提交，任何异常回滚），`Store.read()` 是一个只读快照。WAL、`foreign_keys=ON`。
  schema 版本用 `PRAGMA user_version`（当前 1），重复打开不重复迁移，版本比代码新则拒绝启动。
  时间一律 ISO 8601 UTC 到秒（`iso()` 向下取整，拒绝无时区的 datetime）；id 为 `前缀_16 位 hex`。
- `records.py`：接收连接的行级函数（可在一个事务里组合）；`Store` 上有同名的单事务包装
  （`upsert_user`、`create_conversation`、`get_conversation`（带归属）、`list_conversations`（含 `preview`）、
  `set_conversation_title`、`add_message`、`list_messages`、`add_llm_call`、`add_tool_call`、`list_*`）。
- 表：design §7 的 7 张表，外加：
  - `messages.seq`、`llm_calls.seq`、`tool_calls.seq`（自增，保证同一秒内的顺序）；`llm_calls.created_at`、
    `tool_calls.created_at`；
  - `quotes` 增加 `origin`、`destination`、`status_reason`、`created_at`、`presented_at`、`closed_at`；`legs` 的每段含
    `from / to / distance / from_coord / to_coord / source`（坐标按库里原文存成字符串）；
  - `tickets` 增加 `origin`、`destination`、`confirmed_message_id`（点的是哪条消息里的卡）；
    `tickets.network_fingerprint` 是**出票复核时**的库指纹，`quotes.network_fingerprint` 是报价时的；
  - **`quote_cards(quote_id, message_id, presented_at, nonce_used_at)` 取代 `quotes.nonce_hash`**（见 §3 决定 1）。
- 库层兜底（应用代码写错也过不去）：`tickets.quote_id UNIQUE`（B5）；触发器「只能给 `presented` 的 quote 写票」
  （B2/B7）、「`booked / expired / stale` 不能再变」（Q3）、「票不可修改」；`status`、`role` 有 CHECK。

### airline（`backend/app/airline/`）
- `service.py`：`Airline(store, networks, *, locks=None, nonce_secret=None, quote_ttl=15min)`，时钟取 `store.clock`。
  - 工具（聊天轮次内调用，返回 `Result(code, data, cards)`）：`find_city`、`quote_route`、`request_booking`、
    `list_tickets`。`data` 只有名字、id 和显示值，给 LLM 用；`cards` 是契约里的卡片对象。
  - `post_assistant_message(...)`：`done` 时刻。一个事务里存 assistant 消息并把其中的 quote / booking_request 卡
    `quoted → presented`，登记 `quote_cards`，返回带 `state.nonce` 的契约 `Message`。
  - `book(user_id, quote_id, nonce)`：唯一的出票入口；`trace`、`tickets`、`messages`、`get_quote` 为读接口。
- `cards.py`：8 种卡片 + `CardState` + `Trace` 的构造函数，只从存档记录渲染；显示值只经 `core.pricing.fmt_km / fmt_usd`。
- `locks.py`：`ConversationLocks`（每会话一把锁，同步 `hold()` 和异步 `hold_async()` 是同一把）。

### 出票 `book` 的检查顺序（全部在会话锁 + 一个 `BEGIN IMMEDIATE` 事务内）
| 步骤 | 规则 | 不满足时 |
|---|---|---|
| quote 存在且属于当前用户 | B1 | `not_found` 404（不区分「不存在」和「别人的」） |
| 未过 15 分钟（`now >= expires_at` 即过期；`created_at` 取整到秒，所以实际年龄不会超过 15 分钟） | B4 | quote → `expired`，`expired` 409 |
| 状态 | B5 / Q3 / B2 | `booked` → `already_booked`（带已有票 id）；`expired` / `stale` → 同名错误；`quoted` → `not_presented` |
| nonce 属于这张 quote 的某张已展示卡片且未用过 | B3 | `invalid_nonce` 409，无任何副作用 |
| 复核：`NetworkProvider.current(strict=True)`（必算内容哈希）→ 每个城市仍在且坐标相同 → `price_path` 重算，各段距离、总距离、价格字符串逐一相等 → `cheapest_route` 仍是同一城市序列和价格 | B6 | 读到且不一致：quote → `stale`（原因写入 `status_reason`），`stale` 409；**库读不到 / 不合法 / WAL 模式：`data_unavailable` 503，不改 quote、不消耗 nonce，同一次点击可重试** |
| 写票 → quote → `booked` → 追加 system 消息「Ticket booked.」+ 票卡 | B5 / B7 | 任何异常整体回滚（nonce 也不消耗） |

拒绝且改了状态（expired / stale）时，先 COMMIT 再抛 `BookingError`。

## 2. 给 T3（agent）/ T5（API）的接口

```python
from app.store import Store
from app.airline import Airline, BookingError, ConversationBusy, ConversationLocks, NotFound, Result
from app.core.network import NetworkProvider

store = Store("data/app.db")                       # 时钟可注入：Store(path, clock=fake)
airline = Airline(store, NetworkProvider(db_path), nonce_secret=os.environ.get("NONCE_SECRET", "").encode() or None)
```

**T3（一轮对话）**
```python
async with airline.locks.hold_async(conversation_id):          # 整轮持有；同步代码用 with airline.locks.hold(...)
    user_msg = store.add_message(user_id, conversation_id, "user", text)
    r = airline.quote_route(user_id, conversation_id, origin, destination)   # Result
    r = airline.request_booking(user_id, conversation_id, quote_id)          # Result，永不出票
    r = airline.find_city(name); r = airline.list_tickets(user_id, city=..., booked_after=...)
    #   r.code: "ok" 或错误码；r.data → 给 LLM（无 nonce）；r.cards → 立即发 SSE `card`（state.bookable 恒为 false）
    store.add_tool_call(user_id, user_msg["id"], name, args, result, latency_ms=...)
    message = airline.post_assistant_message(user_id, conversation_id, text, cards, guard_problems)
    #   → 契约 Message，quote 卡此时才有 nonce；原样放进 SSE `done`
```
- 工具自己**不拿锁**，调用方（轮次）持锁。锁不可重入。
- `Result.code`：`find_city`：`ok / unknown_city / ambiguous_city / no_service`；`quote_route`：再加
  `same_city / unreachable`；`request_booking`：`ok / not_found / quote_expired / stale / already_booked`（带票卡）；
  `list_tickets`：`ok / bad_request`（时间解析不了）。
- `quote_route`、`post_assistant_message`、`messages` 对不属于该用户的会话抛 `NotFound`；`locations.db` 不合法时
  `find_city / quote_route` 抛 `core.network.NetworkDataError`（T3 当作工具失败处理）。
- **nonce 不能进 LLM 上下文**：`Result` 里永远没有 nonce；发给 LLM 的历史请用 `Result.data`，不要用
  `post_assistant_message` / `messages` 返回的卡片。
- quote / booking_request 卡在消息里只存引用 `{"type","id"}`，每次读取时从 quote 行重新渲染（改不了价格）。

**T5（HTTP）**
```python
try:
    out = airline.book(user_id, quote_id, body["nonce"])        # {"ticket": TicketCard, "message": Message}
except BookingError as e:
    return JSONResponse(e.as_response(), status_code=e.status)  # 契约错误体；e.ticket_id（already_booked）
airline.trace(user_id, quote_id)        # Trace；NotFound → 404
airline.tickets(user_id)                # [TicketCard]，新的在前
airline.messages(user_id, conv_id)      # [Message]，卡片状态 = 服务端当前状态（含可用的 nonce）；NotFound → 404
store.get_conversation(user_id, conv_id) / store.list_conversations(user_id) / store.create_conversation(user_id)
```
- `book` **自己拿会话锁**，调用时不要已经持有该锁；它是阻塞调用，放在同步路由（线程池）里；`async def` 路由用
  `await airline.book_async(...)`。等锁默认最多 5 s（`lock_timeout`），超时抛 `BookingError("conversation_busy")` 409。
- `Store` 上所有收会话 id / 消息 id 的方法第一个参数都是 `user_id`，同一事务里查归属，不是自己的抛 `NotFound`
  （`app.store.NotFound`，与 `app.airline.NotFound` 是同一个类）。
- `Conversation` = `store.get_conversation(...)` + `{"messages": airline.messages(...)}`。
- 单进程内共用**同一个** `Airline`（或同一个 `ConversationLocks`）实例，聊天和出票才是同一把锁。

## 3. 需要协调者知道的决定

1. **nonce 是派生的，不入库**：`nonce = "n_" + HMAC-SHA256(secret, quote_id ␟ user_id ␟ message_id)[:32]`，
   与设计「绑定 quote、用户、卡片所在消息」一致。库里只记「哪条消息展示过哪张 quote 的卡」和是否已用
   （`quote_cards`），所以 §7 的 `quotes.nonce_hash` 没有采用。原因：契约要求重新加载会话后卡片仍带可用的 nonce
   （Q2），只存哈希做不到，存明文又不如不存。`nonce_secret` 默认每进程随机：重启后旧页面上的 nonce 失效
   （`invalid_nonce`），刷新即可拿到新的；想跨重启保持，T5 / T7 传入环境变量。**design §7 需要协调者同步。**
2. **nonce 在 `done` 时签发，不在 `request_booking` 时**：契约规定 `card` 事件里 `bookable=false`，`done` 之后才可点。
   `request_booking` 只校验并返回确认卡；这样工具结果里从来没有 nonce。
3. 一张 quote 可以有多张卡（行程卡、确认卡、不同消息），各有自己的 nonce，任意一张可点，票只有一张。
4. `request_booking` 只接受**本会话**的 quote（别的会话的返回 `not_found`）。
5. 复核通过但库文件变过（无关行、同内容替换文件）照常出票；复核要求「仍是最便宜且**同一条**路线」，
   出现等价平手导致规范路线变了也算 `stale`。
6. 复核和提交之间库文件再变的窗口（毫秒级）无法在 SQLite 事务里消除，按「点击时刻的库」处理。
7. 契约 fixture 与真实库的两处出入（fixture 本来就标注为示意，未改契约）：`trace.json` 最后一段 source 写的是
   `locations.connected_hubs(Lima)`，真实库里 Lima 是 hub，实际为 `hub_links(Amsterdam, Lima)`；`"San Jose"`
   精确命中库内城市（core 行为），不产生歧义卡，折叠后才歧义（如 `"san jose"`）。`similar_names` 只在
   `Result.data` 里，契约的 QuoteCard 没有对应字段。
8. `Trace.formula / algorithm` 直接用 core 的常量（文字与 fixture 的示意文字不同，形状一致）。
